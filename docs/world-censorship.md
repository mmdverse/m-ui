# اطلس فیلترینگ — مدل چندکشوری، مهندسی معکوس، و حلقهٔ آزمون

این سند مغزِ کارِ «ابر پروژهٔ بین‌المللی» است: چه چیزی از فیلترینگ کشورها می‌دانیم،
چه چیزی را *خودمان اندازه گرفتیم*، چه چیزی را شبیه‌سازی کردیم، و چه چیزی عمداً
شبیه‌سازی **نشد**. هر عددی که در UI یا تست می‌بینی باید بتواند به یکی از بندهای
همین سند وصل شود.

- مدل: `src/lib/censorship/` (۱۱ کشور × ۱۸ لایه × ۱۵ طرح)
- شبیه‌ساز سانسور: `testenv/censor/` (پایتون، بدون وابستگی بیرونی)
- حلقهٔ آزمون سرتاسری: `testenv/world-matrix.py` (Xray واقعی، مسیرهای واقعی)
- اندازه‌گیری اثر انگشت: `testenv/censor/fpmeasure.py`
- اندازه‌گیری تکه‌سازی: `testenv/frag-probe.py`
- زنجیرهٔ چندگره‌ای: `testenv/transit-lab.py` + `src/lib/censorship/transit.ts`

## ۱) یک جمله برای هر خانوادهٔ فیلترینگ

| خانواده | نمونه | ایدهٔ مرکزی | کد |
|---|---|---|---|
| `gfi` | چین | بازرسی درون‌مسیر + فعال پروب کردن + تشخیص ترافیک کاملاً رمز | `fep_detect`, `active_probe`, `quic_sni`, `tls_in_tls` |
| `tspu` | روسیه | DPI دولتیِ توزیع‌شده که هم TCP و هم رکورد TLS را بازچینش می‌کند | `reassembly`, `ech_drop`, `quic_v1_fingerprint`, `sni_whitelist` |
| `whitelist` | ترکمنستان | فقط «مجازها» رد می‌شوند؛ بقیه نه | `sni_whitelist`, `proto_whitelist` |
| `ja4` | امارات | اثر انگشت کلاینت را با دیتابیس مقایسه می‌کند | `ja4_fingerprint` |
| `open` | — | خط پایه: هیچ‌چیز | — |

منابع هر ادعا در `SOURCES` (countries.ts) با شناسه ذخیره شده و در صفحهٔ اطلس
همان‌ها نمایش داده می‌شوند: TSPU-IMC22، FOCI 2025 (ECH)، net4people #490،
USENIX'23 (FEP)، IMC'20 (Shadowsocks)، USENIX'25 (QUIC)، gfw.report،
vpnsmith 2026، securityledger، fexyn، و اندازه‌گیری‌های خودمان.

## ۲) شش چیزی که خودمان اندازه گرفتیم (نه نقل‌قول)

### ۲/۱ JA3 برای uTLS/chrome **بی‌ثبات** است؛ تصمیم باید JA4 باشد

`testenv/censor/fpmeasure.py` برای هر مقدار `tlsSettings.fingerprint` کلاینت واقعی
Xray را اجرا می‌کند و ClientHello را روی سیم می‌گیرد:

```
chrome    ja4=t13d1516h2_8daaf6152771_8ee26baaef31 (variants=1) ja3_variants=3
default   ja4=t13d1516h2_8daaf6152771_8ee26baaef31 (variants=1) ja3_variants=3
firefox   ja4=t13d1715h2_5b57614c22b0_a06ecb99ca30 (variants=1) ja3_variants=1
random    ja4=t13d1515h2_8daaf6152771_d2a542b11920 (variants=3) ja3_variants=3
```

۱۵ اتصال متوالی با پروفایل chrome، **۱۵ JA3 متفاوت** ولی **یک JA4** داد: کروم ترتیب
چند extension را تصادفی می‌کند و uTLS همان را تقلید می‌کند. نتیجهٔ عملی:
سانسوری که بخواهد «مرورگر مجاز است» را پیاده کند چاره‌ای جز اثر انگشتِ
کانونیکال (JA4) ندارد؛ و ما هم لایهٔ امارات را روی JA4 بستیم:
`ja4_fingerprint` با فهرست `JA4_ALLOWLIST` تصمیم می‌گیرد، و همان دیتابیس از
`fingerprints.ts` (تولیدشده) به `rules.json` و شبیه‌ساز پایتون می‌رود.

نکتهٔ دوم: `default` (بدون فیلد `fingerprint`) دقیقاً همان JA4 کروم را می‌دهد —
یعنی پیش‌فرض Xray هم uTLS/chrome است، نه Go.

### ۲/۲ `streamSettings.fragment` مرده است؛ فقط `finalmask` واقعی است

`testenv/frag-probe.py` (اندازه‌گیری مستقیم روی سیم):

```
بدون تکه‌سازی: رکوردهای handshake = 1 [1818]
با finalmask : رکوردهای handshake = 5 [118, 155, 192, 183, 1106]
```

قالب درست روی Xray 26.3.27:

```json
"finalmask": { "tcp": [{ "type": "fragment",
  "settings": { "packets": "tlshello", "length": "100-200", "delay": "10-20", "maxSplit": "4-8" } }] }
```

کلیدهای قدیمیِ مستندنشده (`lengths`/`delays`) باعث خطای راه‌اندازی می‌شوند، و
`streamSettings.fragment` بی‌صدا نادیده گرفته می‌شود (یک رکورد ۱۷۹۱ بایتی).

### ۲/۳ بعدِ TCP در حلقهٔ آزمایشگاهی قابل ادعا نیست، بعدِ رکورد بله

کرنل نوشتن‌های پشت‌سرهم را روی loopback ادغام می‌کند؛ پس «چند سگمنت TCP دیده شد»
تصادفی است. آن‌چه قطعی است شمارش *رکوردهای TLS* است. به همین دلیل تست‌های ما
`record_split` را ادعا می‌کنند و `tcp_split` را فقط گزارش.

### ۲/۴ سربار هر گره در زنجیرهٔ واقعی

`testenv/transit-lab.py` یک زنجیرهٔ واقعی Xray می‌سازد (client → entry → relay →
exit → origin) و ۱۲ بار می‌سنجد:

```
1 گره: میانه 91.463ms
3 گره: میانه 91.906ms      → سربار هر گره: ~۰.۲ms (بین اجراها تا ۶.۴ms هم دیدیم)
```

اختلاف از این است که هزینهٔ handshake هر گره داخل عدد باشد یا نه. این عدد
«سربار پردازش» است، نه تأخیر جغرافیایی؛ آن یکی روی یک ماشین قابل اندازه‌گیری نیست.

### ۲/۵ کلید خصوصیِ جای‌نگهدار، کانفیگ را از اجرا می‌بندد (rc=23)

```
Failed to start: infra/conf: Failed to build REALITY config. > invalid "privateKey": PLACEHOLDER-REALITY-PRIVATE-KEY
```

این را عمداً حفظ کرده‌ایم: کانفیگ تولیدی `transit.ts` تا وقتی کلید واقعی نگذاری
بالا نمی‌آید. تست‌ها هم همین را تأیید می‌کنند (یک تست، رد شدن کانفیگ جای‌نگهدار را
چک می‌کند و تست دیگر چهار کانفیگِ دارای کلید معتبر را با خودِ Xray اعتبارسنجی می‌کند).

### ۲/۶ FEP چین احتمالاتی است — و همین را تست می‌کنیم

شبیه‌ساز برای هر اتصالِ تازه یک کلید/سالت تازه می‌بیند، پس تصمیم FEP باید
«مخلوط» در بیاید، نه قطعی. اجرای واقعی:

```
cn-ss2022    mixed   fep_detect/mixed/probabilistic    5/8 pass
cn-vmess-tcp mixed   fep_detect/mixed/probabilistic    3/8 pass
```

اگر این دو روزی «قطعاً بلاک» شوند، یعنی شبیه‌ساز ما از واقعیت جدا شده و باید
دوباره اندازه‌گیری کنیم.

## ۳) چیزی که عمداً شبیه‌سازی **نشد**: TLS-in-TLS

لایهٔ `tls_in_tls` در مدل هست (شدت ۴، منبع: Xray discussion #4113 و گزارش‌های GFW)
ولی در شبیه‌ساز پیاده نشده و `simulated: false` علامت خورده. دلیلش اندازه‌گیری است:

```
cn (Vision)  app_records = [69, 1203, 669, 1311, 1417, 19]
ae (Vision)  app_records = [53, 1203, 408, 97, 117]
http سادهٔ داخل تونل هم همان الگو را می‌دهد
```

یعنی padding خودِ XTLS/Vision همان اندازه‌های «ClientHello درونی» (۳۰۰–۷۰۰ بایت) و
حتی رکوردهای ~۱۲۰۰ بایتی را تولید می‌کند. هر قاعده‌ای که بر پایهٔ پنجرهٔ اندازه
بگذارد، هم ترافیک عادی را می‌بندد و هم قابل اعتبارسنجی نیست. تشخیص واقعی GFW
آماری/زمانی است و در حلقهٔ آزمایشگاهی loopback بازتولید نمی‌شود. تصمیم ما: صادق
بودن بهتر از پر کردن جدول است. تست `test_tls_in_tls_not_simulated` جلوی «تقلب»
را می‌گیرد: اگر روزی کسی لایه را شبیه‌سازی‌شده علامت بزند، تست می‌شکند.

## ۴) باگ‌هایی که خودِ حلقهٔ آزمون داشت (و پیدا شد)

۱. **پمپِ غیرمسدودکنندهٔ `proxy.py`**: `sendall` روی سوکت غیرمسدود، وسط پرواز TLS
   `BlockingIOError` می‌داد و `except OSError` آن را «قطعی» می‌دید → پروازهای TLS
   نصفه می‌رسیدند (`TLS alert, decode error (562)` در curl). حالا صف خروجی
   per-socket + `select` روی writable.
۲. **بستنِ سخت با RST**: پروکسی همهٔ اتصال‌ها را با `SO_LINGER=0` می‌بست؛ آخرین
   بایت‌های در راه دور می‌رفت. RST فقط برای «مسدود کردن» است، پایانِ عادی FIN.
۳. **پروسهٔ کهنه پورت را گرفته بود**: هارنس پورت را «باز» می‌دید ولی سانسورِ قدیمی
   روی آن نشسته بود؛ حالا هر سانسور باید خط `"ready"` را در لاگ بنویسد.
۴. **نشان ندادنِ وضعیت نهایی**: تصمیم‌ها وسط راه گرفته می‌شوند؛ شاهدِ تست‌ها حالا
   از وضعیت نهاییِ جریان (بافر بازچینش‌شده) می‌آید، نه از لحظهٔ تصمیم.
۵. **JA3 ناقص از بافر ناقص**: جمع‌کردنِ ClientHello در relay وقتی زود می‌برید،
   فهرست extension ناقص می‌دهد و هشِ غلط می‌سازد (یک‌بار مدل را گمراه کرد).

## ۵) چطور همه‌چیز را اجرا کنیم

```bash
# ۱) مدل: واحد و شبیه‌ساز
python3 testenv/censor/selftest.py                 # ۶۶ بررسی، بدون شبکه
npx vitest run                                     # ۱۱۴ تست (شامل ترانزیت و i18n)

# ۲) حلقهٔ سرتاسری: Xray واقعی روی مسیرهای واقعی
python3 testenv/world-matrix.py                    # ۱۵ کیس → باید ۱۵/۱۵ بدهد
python3 testenv/world-matrix.py --only cn --keep   # فقط چین، زیرساخت زنده بماند
python3 testenv/world-matrix.py --stop             # بستنِ همه‌چیز

# ۳) اندازه‌گیری‌ها (فایل‌های شاهد را بازتولید می‌کند)
python3 testenv/censor/fpmeasure.py --cert /tmp/world-matrix/reality.crt --write-ts
python3 testenv/frag-probe.py
python3 testenv/transit-lab.py
```

`rules.json` (قرارداد مشترک مدل TS و شبیه‌ساز پایتون) از خودِ مدل تولید می‌شود:

```bash
UPDATE_RULES=1 npx vitest run tests/censorship.test.ts
```

و تست‌ها بایت‌به‌بایت بودنش را با مدل چک می‌کنند؛ یعنی امکان ندارد مدل و
شبیه‌ساز بی‌سروصدا از هم جدا شوند.

## ۷) صداقتِ مدل: چه چیزی را *نمی‌دانیم*

- هیچ اندازه‌گیری از **درون** این کشورها نداریم؛ vantage point ما یک ماشین در
  آلمان است. لایه‌هایی که `confidence: reported` دارند از گزارش‌های عمومی آمده‌اند.
- لایه‌های `simulated: false` را شبیه‌ساز اجرا نمی‌کند: مسدودی IP/ASN، فیلتر UDP،
  پروب فعال، مسموم‌سازی DNS، تشخیص با یادگیری ماشین، و TLS-in-TLS. این‌ها در
  امتیاز تأثیر دارند ولی *ادعای* شبیه‌سازی روی‌شان نداریم.
- تصمیم FEP احتمالاتی است؛ عدد «۵ از ۸» بی‌معنا نیست، اما تک‌عدد نیست.
- سربار گره‌ها روی loopback اندازه‌گیری شده؛ تأخیر جغرافیایی مدل نشده است.

## Обзор

**M-UI** — self-hosted панель для управления серверами, прокси-конфигурациями и
туннелями. Она разворачивает реальный доступ на реальных машинах по SSH,
сохраняет ссылки пользователей неизменными и — то, что обычно пропускают —
**моделирует систему фильтрации между клиентом и сервером**, чтобы конфигурацию
можно было оценить до того, как её получит пользователь.

**Свободно и открыто: лицензия MIT — личное и коммерческое использование, самохостинг, без ограничений.**

| | Что это | Где лежит |
|---|---|---|
| **Панель** | Серверы, мониторинг, конфигурации, туннели, пользователи и роли, развёртывание SOCKS5, WireGuard, интерфейс на пяти языках | `src/pages`, `src/lib` |
| **Движок цензуры** | 11 стран × 18 слоёв фильтрации × 15 схем обхода, модель оценки и генерация конфигураций под страну | `src/lib/censorship` |
| **Лаборатория** | Симулятор DPI на Python и сквозной стенд на настоящем Xray, перед которым модель отвечает за свои утверждения | `testenv/censor`, `testenv/world-matrix.py` |

Движок и лаборатория не декоративны: `npm test` ломает сборку, если модель и
симулятор расходятся, если слой объявлен «моделируемым» без измерения за ним,
или если сгенерированный транзитный конфиг Xray не принимает.

## Возможности

| Область | Что делает |
|---|---|
| **Серверы** | Добавление по паролю или SSH-ключу. Соединение проверяется до сохранения; секреты шифруются и никогда не возвращаются API. |
| **Мониторинг** | CPU, RAM, load, uptime и трафик из `/proc` самого сервера, периодическая выборка и график за семь дней. Недоступный сервер помечается устаревшим, а не показывает выдуманные числа. |
| **Конфигурации** | Ссылки VMess, VLESS, Trojan и Shadowsocks с TLS, WebSocket, gRPC, HTTP, KCP, QUIC и CDN; REALITY (`pbk`/`fp`/`sid`); XHTTP в режиме `stream-up`. |
| **Стабильная идентичность** | UUID и пароли создаются однократно, поэтому ссылка не меняется под пользователем. |
| **Развёртывание SOCKS5** | Установка и запуск microsocks на целевом сервере с отдельными учётными данными для каждой конфигурации: `apt`, `dnf`, `yum`, `apk`. |
| **WireGuard** | Пара ключей X25519 и готовый `.conf` для клиента. |
| **Туннели** | Обратные SSH-туннели реально запускаются и останавливаются через OpenSSH. Direct, FRP и WireGuard пока только фиксируются. |
| **Советник по подключению** | Оценивает конфигурацию по профилю сети, в которой она будет работать: сожжённые SNI, закрытые порты, отпечатки uTLS, обработка UDP, списки разрешённых протоколов. |
| **Атлас цензуры** | Отдельная страница для каждой страны: слои фильтрации с серьёзностью и достоверностью, ранжированные схемы с обоснованием, сгенерированная конфигурация победителя, транзитный маршрут и источники. |
| **Транзитная цепочка** | Цепочки вход → релей → выход, реальный конфиг Xray на каждый узел, проверяемый запуском `xray run -test` в тестах. |
| **Доступ** | Сессии JWT, bcrypt, ограничение попыток входа с одинаковым временем ответа, роли проверяются на всех пишущих маршрутах. |
| **Развёртывание** | `docker compose` из исходников или `npm ci && npm run build`. В production панель не стартует без `JWT_SECRET`. |

## Как работает модель цензуры

Для каждой пары (страна, схема) движок отвечает на вопрос: *если клиент
подключится так из этой сети, какие слои фильтрации его остановят и что это
компенсирует?*

**Слои** — 18 механизмов: подмена DNS, сброс по SNI, отброс ECH, пересборка
TCP, отпечаток QUIC v1, эвристики полностью зашифрованного трафика, списки JA4,
списки разрешённых протоколов, блокировка IP/ASN, активное зондирование,
классификация потока, эвристики TLS-in-TLS.

**Схемы** — 15 комбинаций протокола, транспорта, защиты и обфускации: от
`VLESS + REALITY + Vision + finalmask` до чистого `WireGuard`.

**Страны** — 11 профилей с серьёзностью слоя и меткой достоверности:
`measured`, `reported` или `heuristic`.

```text
score = 100 − Σ penalty
penalty = 5 × severity   за открытый слой        (severity 1–5)
        + 3 × severity   за частично закрытый слой
        + 40             если порт схемы заблокирован в стране

85+  устойчиво    65–84  работоспособно    45–64  хрупко    ниже — избегать
```

## Инженерные приёмы по странам

### 🇷🇺 Россия — TSPU / RKN

Самый сложный профиль модели. TSPU стоит в разрыве и хранит состояние:
пересобирает **и** TCP-поток, **и** записи TLS; полностью отбрасывает QUIC v1
Initial больше ~1000 байт; отбрасывает рукопожатия с ECH; блокирует зарубежные
облачные ASN на уровне SYN; по сообщениям с середины 2025 года в ряде регионов
работает **список разрешённых SNI**.

| Слой | Серьёзность | Достоверность | Что смотрит |
|---|:--:|:--:|---|
| `sni_block` | 5 | measured | SNI по списку, плюс замедление остального трафика по SNI |
| `proto_fingerprint` | 5 | measured | Фиксированные рукопожатия: 148-байтный initiation WireGuard, опкоды OpenVPN |
| `reassembly` | 4 | measured | Пересборка сегментов TCP **и** записей TLS |
| `quic_v1_fingerprint` | 4 | measured | QUIC v1 Initial при полезной нагрузке свыше ~1000 байт |
| `ip_block` | 4 | measured | Зарубежные облачные ASN (Hetzner, OVH, DigitalOcean) на уровне SYN |
| `sni_whitelist` | 4 | reported | Режим списка разрешённых SNI (регионально) |
| `ech_drop` | 3 | measured | ClientHello с ECH — с ноября 2024 |
| `udp_filter` | 3 | measured | UDP, кроме DNS |
| `ml_flow` | 3 | reported | Статистическая классификация потока |

**Что работает**

1. **Резать дважды.** Ключевой вывод модели: сегментация TCP сама по себе
   недостаточна, и фрагментация записей TLS сама по себе недостаточна; пара
   ломает пересборку, потому что ни одну из сторон нельзя восстановить
   независимо. `reality-vision-frag` даёт **67 против 32** у того же протокола
   без фрагментации — 35 очков на одном приёме.
2. **Использовать `finalmask`, а не `streamSettings.fragment`.** Измерено на
   Xray 26.3.27: старый ключ даёт одну запись в 1818 байт, `finalmask` —
   **пять записей** `[118, 155, 192, 183, 1106]`, детерминированно.
3. **Считать QUIC v1 закрытым.** По правилу профиля отбрасывается весь поток, а
   не отдельный пакет. Hysteria2 выживает только в варианте с неизвестной
   версией первой Initial, и то частично.
4. **Не включать ECH.** ClientHello с ECH к SNI Cloudflare отбрасывается, то
   есть «приватность» здесь означает потерю соединения.
5. **Не выбирать сожжённый облачный ASN.** Если входной IP в заблокированном
   ASN, всё остальное из списка выше не имеет значения.

**Вердикт:** `reality-vision-frag` — **67/100**, единственная схема в верхней
зоне. XHTTP и CDN дают 41 и 11: они не решают задачу пересборки.

### 🇨🇳 Китай — GFW

Классификатор, а не список. Надёжная часть — подмена DNS и блокировка SNI;
интересная — **обнаружение полностью зашифрованного трафика** с пятью
эвристиками исключения и вероятностным применением, а также расшифровка QUIC
Initial в масштабе.

**Что работает**

1. **Пройти список исключений, а не сломать его.** Эвристики структурные: доля
   печатных символов, самая длинная печатная последовательность, первые
   печатные байты, полоса энтропии popcount и распознаваемый отпечаток
   протокола. Чистый Shadowsocks-2022 проваливает все пять по построению: с
   нулевого байта всё случайно. Обёртка в TLS + WebSocket поднимает оценку с 0
   до 49–88.
2. **Блокировка вероятностная, и стенд это доказывает.** В реальном прогоне
   Shadowsocks-2022 был сброшен на **4–5 из 8** соединений, VMess-over-TCP — на
   **3–5 из 8**, в зависимости от случайной соли в первом пакете. Поэтому кейс
   объявлен `mixed`, а не `block`.
3. **Разносить потоки.** Именно для этого существует XHTTP: при
   `mode: stream-up` выгрузка и загрузка идут в разных потоках, и эвристика,
   которой нужны оба направления одного соединения, теряет опору.
   `reality-xhttp` — лучшая схема страны: **88/100**.
4. **QUIC безопасен только без версии.** Расшифровываемый Initial
   расшифровывается и фильтруется; Initial с неизвестной версией не
   расшифровывается вообще.

**Вердикт:** `reality-xhttp` — **88/100**; `reality-vision-frag` и
`reality-vision` — 76.

### 🇮🇷 Иран — семейство NGFW, национальная фильтрация

Подмена DNS, сброс по SNI и — решающее — **список разрешённых протоколов**:
из страны выходят только DNS и HTTP(S). Туннель, не имеющий формы TLS на
разрешённом порту, отбрасывается независимо от номера порта.

**Что работает**

1. **Стать TLS на 443.** REALITY — кратчайший путь: рукопожатие является
   настоящим TLS-рукопожатием с реальным сайтом, сертификат берётся у
   незаблокированного назначения.
2. **Не отправлять вложенный размерный шаблон.** `flow: xtls-rprx-vision`
   убирает подпись размеров внутренних записей TLS — поэтому простые Trojan и
   VMess-over-TLS здесь деградируют.
3. **Резать на уровне записей и сегментов.** `finalmask` разбивает ClientHello
   на несколько записей TLS с задержкой между ними, поэтому SNI никогда не
   виден целиком в одном сегменте. Старый ключ `streamSettings.fragment` Xray
   25+ игнорирует молча.
4. **Не рассчитывать на UDP.** Любая схема на QUIC или WireGuard здесь даёт 33
   и ниже.

**Вердикт:** REALITY-семейство — **91/100**; всё без формы TLS — 0–45.

### 🇹🇲 Туркменистан — полный список разрешённого

Не фильтр, а список входа: трафик разрешён только для небольшого набора
национальных доменов и одобренных сервисов, ответ по умолчанию — «нет».
**Что работает:** прикрытие через CDN (`ws-tls-cdn` → **80/100**, лучший
результат страны), SNI строго из разрешённого набора, ASN CDN вместо ASN VPS,
никаких схем на UDP.

### 🇦🇪 ОАЭ — список разрешённых отпечатков JA4

Единственная страна, где решает **список разрешённых отпечатков TLS**: DPI
ожидает ClientHello настоящего браузера.

**Что работает**

1. **Отправлять ClientHello браузера побайтово.** Модель разрешает ровно те
   отпечатки, которые браузер действительно выдаёт.
2. **JA4, а не JA3.** Из нашего измерения: 15 последовательных соединений с
   профилем `chrome` дали **15 разных JA3** (Chrome перемешивает порядок
   расширений) и **один стабильный JA4** `t13d1516h2_8daaf6152771_8ee26baaef31`.
   Список по JA3 был бы непригоден.
3. **Не отправлять случайный отпечаток.** Профиль, меняющийся от соединения к
   соединению, никогда не окажется в списке — стенд проверяет именно этот кейс
   (`ae-tls-randomized` → блок, `ja4_fingerprint`).

**Вердикт:** REALITY и схемы с браузерным отпечатком — **94/100**.

## Лаборатория DPI

```text
  клиент xray ──► прокси-цензор ──► сервер xray ──► стенд ──► назначение
  (реальный        (правила          (reality/tls/    dest:9447   http/https
   конфиг)          страны)           ss/vmess)
                   │
```

## Транзитная цепочка

| Узел | Роль | Схема | Зачем |
|---|---|---|---|
| `tr:443` | вход | REALITY + Vision + finalmask, отпечаток Chrome | Единственное плечо, которое видит страна-цензор; все серьёзные слои компенсируются здесь |
| `de:8443` | релей | REALITY + Vision | Входной адрес сменяем: пользователи меняют IP, а не конфиг |
| `nl:2053` | выход | REALITY + Vision | Ближе к службам назначения; это IP, который видит внешний мир |

`hopConfigs()` выдаёт конфиг на каждый узел и клиентский конфиг, а
`tests/transit.test.ts` прогоняет каждый через `xray run -test` со свежими
ключами X25519. Измеренные накладные расходы: **+0.222 ms на узел**
(loopback; географическая задержка не моделируется).

## Быстрый старт

```bash
git clone https://github.com/mmdverse/m-ui
cd m-ui
cp .env.example .env        # заполните JWT_SECRET и ADMIN_PASSWORD
npm ci
npm run build && npm start
```

Панель доступна на `http://localhost:3000`; первый администратор создаётся из
переменных окружения при первом запуске.

```bash
JWT_SECRET=$(openssl rand -hex 32) \
ADMIN_PASSWORD='надёжный-пароль' \
MONGO_PASS='пароль-базы' \
  docker compose up -d
```

<details>
<summary><b>Переменные окружения</b></summary>

| Переменная | Обязательна | Назначение |
|---|:--:|---|
| `JWT_SECRET` | ✔ (production) | Подпись сессий; в production без неё панель не стартует |
| `MONGODB_URI` | ✔ | Строка подключения MongoDB |
| `M_UI_ENCRYPTION_KEY` | рекомендуется | Шифрование сохранённых секретов независимо от `JWT_SECRET` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | первый запуск | Создание первого администратора (минимум 8 символов) |
| `PORT` | — | Порт панели, по умолчанию 3000 |

</details>
